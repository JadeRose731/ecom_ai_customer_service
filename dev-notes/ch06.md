### A —— 非流式 `ainvoke`(Task 13 run_turn/resume_turn)

中断时 `ainvoke` **正常返回不抛异常**,返回 dict 多一个 `__interrupt__` 键:

```python
out = await graph.ainvoke(input, config)
pending = out.get("__interrupt__")            # None/缺键 = 无中断;容器是 list[Interrupt]
if pending:
    payload = pending[0].value                # {"type": "select_order", "orders": [...]}
# resume:同 config(同 thread_id),从被中断节点【头】重跑,interrupt() 处返回 v
out2 = await graph.ainvoke(Command(resume="1001"), config)
out2["picked"]                                # == "1001"
```

- 实测 keys:中断时 `['messages', '__interrupt__']`(被中断节点还没写 picked);resume 完成后 `['messages', 'picked']`,**`__interrupt__` 键消失**。
- `Command(resume=v)` 从被中断节点**头**重跑已证实(冒烟 B 段 picked 生效、AI 消息拼接 `已选订单 1001`)。

### C —— `astream(stream_mode=["messages","updates"])`(Task 13 stream_turn)

中断以 **updates 模式的 chunk** 浮出,键名 `__interrupt__`,值 `tuple[Interrupt, ...]`(实测出现,True):

```python
async for mode, chunk in graph.astream(input, config, stream_mode=["messages", "updates"]):
    if mode == "updates" and "__interrupt__" in chunk:
        payload = chunk["__interrupt__"][0].value     # 中断 chunk:{"__interrupt__": (Interrupt(...),)}
```

探 pending 兜底路径(`aget_state`,两字段等价):

```python
snap = await graph.aget_state(config)
snap.next                # ('ask_order',) —— 停在哪个节点
snap.interrupts          # (Interrupt(...),) —— 1.2.11 StateSnapshot 顶层就有此字段
snap.tasks[0].interrupts # 同一个 tuple
payload = snap.tasks[0].interrupts[0].value
```

- 流式 resume(`astream(Command(resume=v), config)`):updates 依次 `{'ask_order': {'picked': '2002'}}` → `{'confirm': {...}}`,完成后**没有** `__interrupt__` chunk。
- **messages 模式 0 chunk(重要)**:纯节点图无 LLM token 时一个 messages chunk 都没有;且 1.2.11 上节点写回 channel 的完整消息(如 confirm 的 AI 消息)**不会**以 messages 模式重放。Task 13 别指望从 messages 模式拿 AI 文本,拿节点结果走 updates。

### D —— 图外直接调节点(Task 7 fetch_order 单测断言)

**裸调不成立**:`await ask_order({...})` 不抛 `GraphInterrupt`,抛 `RuntimeError: Called get_config outside of a runnable context`(源码:`get_config()` 无 contextvar 即 raise)。单测须带最小 runnable 上下文:

```python
from itertools import count
from langchain_core.runnables.config import var_child_runnable_config
from langgraph._internal._scratchpad import PregelScratchpad
from langgraph.errors import GraphInterrupt

def interrupt_test_config() -> dict:
    return {"configurable": {
        "thread_id": "test", "checkpoint_ns": "",
        "__pregel_scratchpad": PregelScratchpad(
            step=0, stop=1,
            call_counter=count(1).__next__, interrupt_counter=count().__next__,
            get_null_resume=lambda _consume: None, resume=[],
            subgraph_counter=count(1).__next__,      # 必填,漏了 TypeError
        ),
    }}

token = var_child_runnable_config.set(interrupt_test_config())
try:
    with pytest.raises(GraphInterrupt) as ei:
        await ask_order({"messages": []})
    payload = ei.value.args[0][0].value    # {"type": "select_order", "orders": [...]}
finally:
    var_child_runnable_config.reset(token)
```

- `e.args` 形状(实测原样):`((Interrupt(value=…, id=…),),)` —— 1-tuple 包 tuple[Interrupt],载荷取 `e.args[0][0].value`。
- 备选(不想依赖 `langgraph._internal` 内部 API):用 mini 编译图实跑断言 `out["__interrupt__"][0].value`(A 路径),效果等价。

### 关键注记(写断言前必读)

- **Interrupt.id 勿 hardcode**:`id = xxh3(checkpoint_ns)` 派生,跨进程/跨 thread 不稳定(三次运行三个值);断言只打 `.value`。
- **给 Task 7 的 Token 泄漏提示**:`var_child_runnable_config.set()` 必须配 `try/finally + reset(token)`(如上),否则假 config 沿 contextvar 泄漏到后续代码;且 pytest 配置是 `asyncio_default_test_loop_scope = "session"`,同 loop 跨测试共享,泄漏面更大——每个用例 set/reset 成对。
- **容器类型差异**:`__interrupt__` 在 ainvoke 返回里是 **list**,在 astream updates chunk 与 aget_state 里是 **tuple**;断言别写死容器类型,取 `[0]`/`[0]` 即可。
- `AsyncSqliteSaver.from_conn_string(":memory:")` + `await cp.setup()`:与 plan 一致零差异(3.1.1)。
- `PregelScratchpad` 是 `langgraph._internal._scratchpad` **内部 API**(1.2.11),升级时是首个可能破坏 D2 取法的点——冒烟 D2 段就是哨兵,升级后先跑 `make smoke-interrupt`。
