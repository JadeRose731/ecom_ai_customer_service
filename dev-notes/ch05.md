- `graph.astream(inp, config, stream_mode=["messages","updates"])` 产出 `(mode, chunk)` 元组:
  - `messages` 模式:`chunk = (msg, metadata)`,token 归属节点在 `metadata["langgraph_node"]` —— /api/chat 的 delta 就按这个过滤(agent_llm / chitchat_reply / complaint_reply 才下发,tool 等节点不下)。
  - `updates` 模式:`chunk = {node_name: state_delta}`,拿 citations/actions/answer 终值靠它。
- `add_messages` reducer 正常;thread_id 走 `config["configurable"]["thread_id"]`。

## T2 祛魅裸 Agent 循环

**关键产出**
- `scripts/bare_agent_loop.py`:纯 for 循环 Agent——`get_chat_model().bind_tools(get_all_tools())`,循环里 `ainvoke → 无 tool_calls 收敛 / 有则逐个 execute_tool_call 回灌 ToolMessage`,max_turns=6 封顶打兜底提示。零框架依赖,直接复用 ch02 的工具注册与执行基建。

**祛魅结论**
- Agent 本体 = 带工具清单的 for 循环:LLM 每轮要么给 tool_calls(继续),要么给纯文本(收敛)。所谓"框架"做的事只有三件:把循环放进更大的图(与确定性工作流混排)、把中间态持久化(checkpointer)、把流式和事件流标准化(astream 多模式)。这三件正是 T3 起LangGraph 接管的。

## T3–T9 节点与分类器(要点)

- State:`messages` 用 `add_messages` reducer、`trace` 用自写 `merge_dict`(后写覆盖);`total=False` 允许渐进填充。
- 意图分类:`with_structured_output` + 扁平单字段(避开 glm 嵌套 502,与 ch01 extract 同一教训),异常/越界回退「闲聊」最保守出口。
- `forced_rag` 复刻 query_faq 两道闸(机械分闸 + 语义自评闸)但结果落 State;`confidence_check` 是实体节点只留痕,真正分流在条件边。
- ReAct 环停止只看「无 tool_calls / 步数≥6」;token 逐步累加进 trace 给 ch09,不当停止条件(spec D 决策)。
- `agent_tools` 拦截 `create_ticket`:不执行不写库,转 `suggested_actions` + 合成 ToolMessage 促收敛;真正写库在按钮端点(用户确认后才落 tickets)。

## T10–T15 组装 / 运行时 / API / 前端

- build:六段接力 + 三条件边(route_by_intent / confidence_gate / should_continue),结构测试只查节点名与可编译。
- runtime:`from_conn_string` 的 CM 持在模块级 `_cm` 防 GC;lifespan 起、yield 后关。stream_turn 把双模式流映射成 delta/tool/citations/actions/done 事件,确定性出口的 answer 整块作 delta。

- /api/chat 事件循环逐帧转 SSE,新增 `actions` 帧;错误三路径(404 会话/503 库/502 上游)沿用。
