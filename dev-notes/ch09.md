## Task 2:Langfuse 部署物 + 配置 + 编译时挂回调

- **用户原话**:「继续」。
- **API 口径以安装版实测为准**:`uv add langfuse` 实装 **4.15.4**(v4 SDK),逐条查证:
  1. `Langfuse(public_key=, secret_key=, host=)` ✓(host/base_url 两参名都收,取 README 口径 host);
  2. `langfuse.langchain.CallbackHandler()` 无参构造 ✓;handler 源码确认 config metadata 映射:`langfuse_session_id`→session_id 等(runtime 三处 config 的 metadata 写法成立,实测 trace 落对 session);
  3. **偏差①(重写)**:`get_client().update_current_trace()` 在 4.x 已删除;且服务端 v4 是 **events_only 模式**——REST `POST /api/public/traces` upsert 404、`api.trace.get/list` 退役,「事后补写 trace」路线整条不通。**替代**:tag_intent 走 trace 级 OTel 属性(见偏差④)。
- **偏差②**:Plan 说「Langfuse v3 自部署」,官方 compose main 现发 **v4 镜像**;SDK 已是 4.15.4,服务端与 SDK 同代对齐,维持自部署选型不变,取 v4。
- **偏差③(v4 Metrics API 实测口径,Task 11 依赖)**:`api.metrics.get` 不存在;可用的是 `api.metrics.metrics(query=json.dumps({...}))`,且 **traces 视图不支持(events_only),只有 observations 视图**;字段名 `metrics`(非 measurements)、聚合键 `aggregation`(非 agg);tags 过滤必须 `type: "arrayOptions"` + `operator: "any of"` + 数组值。cost 脚本按此口径写。
- **偏差④(意图标注机制,考证链全文)**:Plan 设计「tag_intent 里 update_current_trace 补 tags/metadata」在 v4 双重不可用后,对 SDK/服务端源码+实机做了系统排查:
  1. **tags 是 trace 级 OTel 属性**(`langfuse.trace.tags`),observation 没有自己的 tags 列;Metrics observations 视图的 tags 维度按「**各 span 自身导出时携带的该属性**」分组;
  2. **LangGraph 每个节点跑在独立 asyncio task**(上下文副本),propagate_attributes 的 attach 出不了本节点 task——classify 节点里 attach,后续节点建的 LLM span 拿不到(对照组实证);
  3. span_processor `on_start` 会把 propagated 属性复制到新建 span 上 → **产生模型调用的节点入口各自 attach 一次**,该节点内后续 LLM observation 全带 tag(实机验证:`intent:商品咨询` 正确分组);
  4. **坑(已绕开)**:`propagate_attributes(...).__enter__()` 丢弃 CM 临时对象会被 GC,generator 关闭触发 `finally: detach`,attach **立刻被撤销**(`with` 块写法因持有引用而正常)——此前「metadata kwarg 之谜」实为该 GC 效应的误判。绕开姿势:直接 `otel_context_api.attach(set_value("langfuse.propagated.tags", tags, current))`,不用 CM、不持 token;LangGraph 节点 task 结束上下文副本自然丢弃,无泄漏。键名 `langfuse.propagated.tags` 为 SDK 4.15.4 内部常量(升级 SDK 需回归 smoke)。
  5. trace 详情页显示 tags 另走通道 1:handler 挂的 root observation 图终才导出,运行中 `root_span.set_attribute("langfuse.trace.tags", tags)` 即时生效。
  - 结论写进 `tag_intent` docstring;**节点接线(Task 3/5)**:classify_intent 调一次(trace 级 + 本节点),产生模型调用的节点(agent_llm/forced_rag/retrieve_policy)各自再调一次(按意图分组建模靠这个),比 Plan 的「只挂 classify 一处」多两处,偏差已记。
